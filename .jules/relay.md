## 2024-05-27 — Background message handler and alarm fixes
**Finding:** The background service worker had several message handlers that incorrectly returned `false` for unknown messages (which isn't best practice for async channels), the CQD_DOWNLOAD handler didn't return `true` to keep the channel open after initiating an async download response, and the cleanup routines were registered using `setInterval` and `setTimeout`, which do not survive service worker termination.
**Action:** Replaced `setInterval`/`setTimeout` with `chrome.alarms.create` for `cleanupOrphanedPendingDownloads`. Updated message handlers to return `void` (or `undefined`) instead of `false` when ignoring messages. Updated the `CQD_DOWNLOAD` handler to return `true` to indicate an async response.
**Learning:** Always use `chrome.alarms` for background tasks, and properly manage `return true` for async `onMessage` listeners while returning nothing for ignored messages to avoid closing channels unexpectedly.
