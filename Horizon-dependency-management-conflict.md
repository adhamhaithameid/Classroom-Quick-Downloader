**Agent:** Horizon | **Day:** Thursday | **Date:** 2026-06-25

### 🏗️ Architecture Area
Dependency Management / Mono-repo Tooling

### 🔍 Current State
Currently, the repository employs two different dependency management tools simultaneously. There is a `.github/dependabot.yml` configured to manage npm dependencies independently for the `/extension`, `/cloudflare-worker`, and `/oracle-backend` subdirectories. Concurrently, there is a root-level `renovate.json` that manages dependencies for the entire repository. This setup is problematic for a `pnpm` workspace mono-repo. Dependabot, configured per directory, does not respect the root `pnpm-workspace.yaml` and lockfile effectively, often leading to duplicated PRs, lockfile conflicts, and uncoordinated updates across workspaces sharing the same dependencies.

### 💡 Proposed Improvement
Consolidate dependency management across all workspaces by relying entirely on Renovate and completely removing Dependabot.
- **Remove Dependabot:** Delete the `.github/dependabot.yml` file.
- **Enhance Renovate:** Update the `renovate.json` configuration to ensure it effectively manages `pnpm` workspaces. Ensure it groups related updates across all workspaces (e.g., updating TypeScript or ESLint simultaneously in `extension`, `cloudflare-worker`, and `website`).
- **Coordinate Updates:** Renovate natively understands `pnpm` workspaces and will update `pnpm-lock.yaml` correctly at the root, ensuring synchronized updates for shared dependencies.

### 🎯 Why This Matters
Running both Dependabot and Renovate creates noise, duplicated effort, and lockfile conflicts. Dependabot's directory-by-directory approach breaks the fundamental promise of a `pnpm` workspace, where dependencies should be hoisted and managed centrally. A single workspace update might pass its own CI but fail integration when combined with older dependencies in other workspaces. Renovate's workspace-aware grouping ensures that a shared dependency (like `typescript`) is updated atomically across the entire repository, maintaining type consistency and preventing "works on my machine/workspace" issues.

### 📐 Acceptance Criteria
- [ ] `.github/dependabot.yml` is deleted.
- [ ] `renovate.json` is configured to group updates for common dependencies across the mono-repo.
- [ ] A single PR generated by Renovate correctly updates a shared dependency across multiple workspaces and correctly updates the root `pnpm-lock.yaml`.

### 🔧 Technical Context
- **Files Modified:** `.github/dependabot.yml` (deleted), `renovate.json` (modified).
- **Workspaces Affected:** Applies to all packages managed by `pnpm` (`extension`, `cloudflare-worker`, `oracle-backend`, `website`).

### 📊 Estimated Complexity
Small (1–2 days). This involves deleting one file and making minor adjustments to an existing `renovate.json` file. It's mostly a configuration change.

### ⚠️ Risks and Considerations
- **Security Alerts:** Dependabot is also used by GitHub for security alerts. We need to ensure that removing `.github/dependabot.yml` (which manages *updates*) does not inadvertently disable GitHub's native Dependabot *alerts* (which run independently of the update configuration file).
- **Renovate Configuration:** Ensuring Renovate is correctly tuned to avoid overwhelming the team with PRs while still keeping dependencies up-to-date.
