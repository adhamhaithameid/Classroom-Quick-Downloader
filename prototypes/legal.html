Legal & trust surfaces

What users must see to keep the extension compliant and trusted: privacy disclosure, permission explanations, the "Not affiliated with Google" notice, the API-beta risk warning, and a copyright reminder for downloaded materials. Each is rendered as it would ship, labeled REQUIRED (store policy demands it) or RECOMMENDED (not demanded, but protects users and the listing). Full mapping in the summary table below.

01 · Privacy / data-use disclosure

A footer row in the popup, expanding in place

Store level: the privacy policy itself is REQUIRED (dashboard + listing) and data practices must be "prominently disclosed" with affirmative consent before install. In-product, the popup gets a one-tap summary row — users should never leave the popup to learn where their files go. Click the row to expand it.

REQUIRED · store + dashboard

In-product summary row

Why: the store listing can carry the full policy, but the moment of truth is in the popup. The summary states the three facts users care about: what is read, what is stored, what leaves the machine.

Popup · footer
v1.8.9

Where your files and data go

Classroom Quick Downloader reads the page you are on and downloads its attachments to your computer.

  • Reads: the Classroom pages you open, to find posts and attachments.
  • Stores: your settings on this device. No account, no analytics.
  • Sends: nothing to the developer. Downloads go from Google to you, directly.
Full privacy policy ↗
Placement: popup footer (collapsed) + Options page (same content, expanded) + store listing (policy link). One source of truth so the three never contradict — contradictions are grounds for removal.
RECOMMENDED · in-product

Copy rules for the summary

Why: disclosure copy fails when it is vague ("we may collect data to improve the product"). The summary uses concrete nouns: pages, settings, nothing.

  • · Lead with the data direction (in / stored / out), not with legal hedging.
  • · "No account, no analytics" — say what you do not do.
  • · Link the full policy; never inline the whole policy in the popup.
  • · Same three lines verbatim in Options and on first run (if adopted).
  • · Update the store listing before shipping any change in data practice — post-install changes must be prominently disclosed.
Store-side REQUIRED items this supports: accurate privacy policy posted and linked in the dashboard; data-use disclosures in the dashboard matching real behavior; the Limited Use affirmation (surface 06).
02 · Permissions explainer

Every permission, one plain-language reason

Store level: justifications are REQUIRED in the dashboard — "request access to the narrowest permissions necessary" and explain each one. In-product: RECOMMENDED, best shown in Options and at first run, not only on the listing. The API-beta permission only appears once the beta is relevant.

REQUIRED · dashboard justification

Options page · "Permissions we use"

Options · Permissions section
Downloads Saves attachments to your computer's Downloads folder and shows their progress. chrome.downloads · core feature
Storage Remembers your engine choice and highlight settings on this device. chrome.storage.local · settings only, never files
Your Google account — API beta only Lets the beta list your own Classroom files via Google's official API. The token stays in the browser and is never sent to the developer. chrome.identity · appears only when the beta is offered
Rule applied: narrowest-permission first — identity is presented as scoped to the beta, which matches the registry behavior (v3 activates only when isApiConfigured()).
RECOMMENDED · in-product

Why show this in-product at all

Why: Chrome shows a coarse permission prompt ("Read and change your data on classroom.google.com"); users still file distrust complaints. A precise, friendly mapping of permission → benefit closes the gap the OS prompt creates.

  • · One row per permission, verb-first ("Saves…", "Remembers…", "Lets…").
  • · Name the mechanism in faint text (chrome.downloads) — trust through specificity.
  • · The identity row only renders for users who see the API beta.
  • · Reuse these exact strings in the store listing's permission justifications.
Store-side REQUIRED anchor: the dashboard justification text itself (one per permission). This prototype supplies copy that can be pasted there, keeping store and product aligned.
03 · "Not affiliated with Google"

Footer notice, always visible, never hidden in a menu

Store level: impersonation and false-endorsement policy — the extension must not "represent that your product is authorized by, endorsed by, or produced by" Google. The product name and the Classroom integration make a standing disclaimer the only safe posture, so it is treated as REQUIRED mitigation.

REQUIRED · mitigation

Popup footer + About card

Popup · footer
Not affiliated with Google. Classroom Quick Downloader is an independent tool and is not endorsed by Google. Downloads belong to their owners — follow your school's policies.
Copy rules: one line, 10px, in the permanent footer of the popup and in the Options About card · first sentence is the disclaimer itself (not buried after marketing copy) · same sentence on the store listing description, first paragraph.
RECOMMENDED · listing hygiene

Where else it must (and must not) appear

  • · Required: store listing — disclaimer in the description; no Google logos, Classroom UI screenshots recolored, or "for Google Classroom ™" wordmarks that imply production by Google.
  • · Required: no fake system-dialog styling anywhere in the UI (policy prohibits simulating system warnings).
  • · Recommended: keep "Google Classroom" out of the extension's display name if a reviewer ever pushes back on trademark grounds — the current name "Classroom Quick Downloader" was a good call.
Why REQUIRED here: the notice is the cheapest, most robust mitigation against an impersonation strike; omitting it while naming Classroom in copy is the risk combination.
04 · API (beta) risk warning

Shown at selection time, inside the selector's context

No store rule mandates a beta warning, but "features must be stated clearly and in a transparent manner" — and the beta changes the trust model (an OAuth scope is added). Marked RECOMMENDED, strongly advised; it renders when the user selects API (beta) and in Options next to the engine cards.

RECOMMENDED · transparency

Warning card on beta selection

Popup · below engine selector
API (beta) is experimental

Uses Google's official Classroom API with your sign-in. It can be slower to start and may break when Google changes. Legacy and New stay one click away.
Copy rules: name the risk ("experimental", "may break"), name the mechanism ("Google's official API"), and end with the rollback promise — fear first, safety last line.
RECOMMENDED · consent trail

What the warning must connect to

  • · The OAuth consent screen (Google's own) is where the user actually grants access — this card only prepares them for it.
  • · If getAuthToken(interactive:false) fails and interactive consent is about to trigger (engine-v3 token path), show the same card once before the prompt.
  • · Options page repeats it verbatim next to the API radio card.
Escalation path: if Google requires a verification for the scope, the dashboard disclosure (REQUIRED) carries the legal weight; this card carries the user trust.
05 · Copyright / ToS reminder for downloaded materials

One-time dialog before the first classroom-wide download

No CWS clause demands this verbatim, but the policy prohibits facilitating illegal activity, and bulk-downloading an entire classroom is exactly where overzealous use begins. A one-time, check-box-gated reminder before the first big run is marked RECOMMENDED (strongly). It fires once per profile, then the classroom button carries a one-line footer echo.

RECOMMENDED · strongly advised

First-run dialog · classroom action

Before you download everything

Materials in this classroom belong to their owners — your teachers and school.

Keep downloaded files for your own study. Follow your school's rules and the Google Workspace for Education terms. Do not share or repost them.

Copy rules: "belong to their owners" names the duty holder; the checkbox is affirmative and specific ("responsibly", not "I agree" — nobody reads "I agree"); dismiss without checking = no download. Try the checkbox — the button unlocks.
RECOMMENDED · persistence

After the first time

  • · Store the acknowledgment as a flat key (e.g. ipReminderAcknowledged) — matches the store's flat-key constraint.
  • · The classroom button's sub-line keeps a standing echo: "Files belong to their owners."
  • · The popup footer already carries the same line (surface 03) — one rule, three echoes, no dialogs after the first.
Why not REQUIRED: a downloader is a neutral tool; Google Drive files the user already has classroom access to are not "circumvention". But when the tool scales from 3 files to 3,000, the reminder is cheap insurance for the listing and the right nudge for the user.
06 · Limited Use affirmation

The one-line API statement, in Options

Because the API beta uses Google APIs, the store requires an affirmative statement that data use complies with the Chrome Web Store User Data Policy (Limited Use). Store level: REQUIRED (dashboard + policy page). In-product echo in Options: RECOMMENDED.

REQUIRED · store + dashboard

Options · About card, API section

API (beta) — data use

Only used to list and download files from classrooms you are enrolled in.

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.
Placement: the exact sentence must appear in the dashboard disclosure and the linked privacy policy; showing it in-product costs one line and preempts review questions.
RECOMMENDED · keep it human

The human line above the legal line

  • · Plain line first: "Only used to list and download files from classrooms you are enrolled in."
  • · Legal sentence second, verbatim from policy, smaller and dimmer.
  • · Never merge the two into one paragraph — reviewers look for the exact sentence; users read only the plain one.
Summary of store-level items: privacy policy posted + linked · data disclosures accurate · Limited Use affirmation · permission justifications. All four live in the dashboard; surfaces 01–02 keep the product consistent with them.
