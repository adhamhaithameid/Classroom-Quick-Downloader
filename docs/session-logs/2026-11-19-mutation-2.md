## Equivalent mutants (cannot be killed; proofs)

token-source.ts
- 191 L69 `/=+$/` -> `/=+/`: base64 of `btoa` only emits `=` as trailing padding, so removing
  the end anchor changes nothing.
- 241 L180 `if (this.inflight === pending)` -> `true`: getToken checks `if (this.inflight)`
  synchronously before every `track()` (no await between), so `inflight` is only ever assigned
  while null, and only the finally callback clears it. At finally time inflight is always
  `pending`.
- 268 L208 catch `{ return null }` -> `{}`: `redirect` stays undefined and the next line
  `if (!redirect) return null` returns the same value.
- 271 L211 `if (!redirect)` -> `false`: an undefined/empty redirect then reaches `redirect.startsWith`
  inside the try; the TypeError (or false startsWith for '') lands in the catch which returns null.
- 301 L247 `json?.access_token` -> `json.access_token`: a null json throws a TypeError inside the
  try, whose catch returns null (same result).

capability.ts
- 44 L79 `: []` -> `['Stryker was here']`: used only for `includes('Brave')` and
  `isGoogleChromeBrand`; the junk string matches neither.

config.ts
- 86, 87 (`navigator?.` / `uaData?.` dropped): the TypeError is thrown inside the try and the
  catch returns [].
- 91, 92, 94: placeholder strings/arrays replace '' or [] in brand names; no consumer matches
  them ('Google Chrome' / 'Brave' only).
- 93 catch `{}`: returns undefined; both consumers (`isGoogleChromeBrand`, probe `brands`)
  guard with Array.isArray, so undefined behaves as [].
- 105 L100 `!chrome.runtime?.getManifest` -> false: calling a missing getManifest or reading
  getManifest off an undefined runtime throws inside the following try, which returns false.
- 169 L141 `''` -> junk UA when navigator is absent: the probe answers 'none' for an empty and for
  an unrecognizable UA.
- 176 L147 `chrome.runtime?.sendMessage`: runtime is already proven defined by the getManifest guard.
