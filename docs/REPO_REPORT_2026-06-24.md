# CQD Repository Report — 2026-06-24

Generated by full-repo audit. Covers all components, CI/CD, security, docs, and open work.

## Executive Summary

CQD is a **production-grade distributed analytics + browser extension system** running at **$0/month** on free tiers. The architecture is sound, test coverage is strong, and the extension is in a stable 1.5.5 release. The primary maintenance burden right now is:

1. **65 open Jules agent PRs** accumulating weekly — most are merge-ready but unreviewed.
2. **Two Oracle P0 regressions** (sessions, Sheets export) blocking Oracle expansion.
3. **No automated store publishing pipeline** — builds exist but distribution is fully manual.
4. **Security alert noise** — most already patched via overrides; `shell-quote` CRITICAL fixed 2026-06-24.

---

## Architecture Overview

```
Browser Extension (WXT/React, v1.5.5)
  └─ analytics events → Cloudflare Worker (v3.0.0)
       └─ Durable Object (batch buffer, strong consistency)
            └─ POST /ingest-batch → Oracle Backend (Go 1.24, SQLite WAL)
                  ├─ async relay → Postgres (outbox pattern)
                  ├─ Google Sheets archiver (daily)
                  └─ public API → Website (SvelteKit 5, Cloudflare Pages)
```

**Cost model:** Cloudflare Workers free tier (~5K/100K req/day), Oracle Cloud free Ampere A1 (1 OCPU/1GB), Google Sheets API unlimited. **Total: $0.00/month.**

## Key Findings

1. **Jules agent backlog is the biggest operational risk.** 65 PRs open. Most are merge-ready but nothing has been reviewed. Weekly cycle generates ~10 new PRs. Without a review cadence, this will grow unbounded.

2. **Oracle is blocked by two P0 regressions** before any expansion work. Fix sessions, fix Sheets export, then expand.

3. **Extension is in great shape** but has a hidden race condition (`pendingByUrl`) and an incomplete v3 engine that need scoping before 1.6.0 planning.

4. **Distribution is a manual bottleneck.** Extension is built in CI but store publishing is entirely manual. Hybrid CI pipeline will remove this bottleneck.

5. **Worker hardcodes Oracle by IP** (`129.151.233.229.nip.io`) — fragile. Should be a domain-based endpoint configured by secret.

6. **Test coverage gaps:** website and oracle Go have no codecov integration. CodeQL misses Go entirely. Go modules missing from Dependabot.
