- Why this is now done:
  - `cloudflare-worker/wrangler.toml` now commits an HTTPS placeholder endpoint (`https://oracle-endpoint-placeholder.invalid`), not a raw HTTP Oracle IP.
  - `ALLOW_INSECURE_ORACLE_ENDPOINT` is no longer committed in worker config defaults.
- Remaining risk:
  - Runtime `.dev.vars` or ad-hoc CI injection can still set an insecure HTTP endpoint.
  - Local/provisional deploys can still bypass HTTPS if `allowInsecureHttp` is explicitly enabled.
- Guardrails to keep:
  - Keep insecure HTTP only for explicit local migration use.
  - Never commit real Oracle IP/HTTP endpoints into tracked config.
  - Keep docs explicit that production Oracle endpoint must be HTTPS.
- How to verify continuously:
  - CI grep/check should fail if committed config reintroduces `ALLOW_INSECURE_ORACLE_ENDPOINT=true`.
  - CI should fail if committed `ORACLE_ENDPOINT` starts with `http://` for non-loopback targets.
- Affected files/functions:
  - `cloudflare-worker/wrangler.toml` (`ORACLE_ENDPOINT`, `ALLOW_INSECURE_ORACLE_ENDPOINT`)
  - `cloudflare-worker/src/oracle-endpoint.ts` (`resolveOracleEndpoint`, insecure guard bypass at `allowInsecureHttp`)
  - `cloudflare-worker/src/index.ts` (calls to `resolveOracleEndpoint`)
  - `cloudflare-worker/src/downloads_do.ts` (calls to `resolveOracleEndpoint`)
